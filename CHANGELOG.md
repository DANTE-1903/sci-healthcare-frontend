The picker is bounded by the contract's own rule and nothing more: `create_voucher` rejects an `expires_at` that is not strictly in the future (`InvalidExpiry`, #9) and sets no latest date, so the earliest date offered is today (UTC) and there is no upper bound. - Content-Security-Policy and companion security headers on every route (`next.config.ts`, #73). The policy is built from the same build-time variables the client bundle reads, so it allows exactly the origins the app uses — the indexer API, Soroban RPC, Horizon, the wallet hosts the SEP-43 kit talks to (`albedo.link`, `wallet.xbull.app`, wallet icons on `stellar.creit.tech`), OpenStreetMap tiles and the optional Plausible/Sentry origins — and refuses everything else, including injected third-party scripts. It ships as `Content-Security-Policy-Report-Only` so violations can be watched in a real deployment before enabling it; build with `CSP_ENFORCE=1` to send the enforcing header. Also sets `frame-ancestors 'none'` with `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin` (paths such as clinic addresses and voucher ids never leak cross-origin), a restrictive `Permissions-Policy`, `X-Content-Type-Options: nosniff`, `Cross-Origin-Opener-Policy: same-origin-allow-popups` (xBull and Albedo sign in a popup and need the opener) and HSTS on production builds.
- A production build now stops, with an itemised message naming every missing variable and what it breaks, instead of succeeding and failing in the user's browser on the first contract call (`next.config.ts`; #76). Validates the eight required variables, that the API and RPC URLs are absolute, and that contract ids look like contract ids. Only `next build` is checked — the config is exported as a function and the validation runs for `PHASE_PRODUCTION_BUILD`, so `next dev` and Storybook are untouched — and CI now fails if a build without `NEXT_PUBLIC_VOUCHER_CONTRACT_ID` succeeds.
- Installable app with an offline shell (#74): a web app manifest (`src/app/manifest.ts`) with generated icons at the two sizes install prompts require plus a maskable one, and a hand-written service worker (`public/sw.js`) that caches the shell — the `/` document, the manifest, the icons and the content-hashed build output — so the app opens on a dead connection and says plainly that it cannot reach the indexer. Never cached: the indexer API, Soroban RPC, Horizon, map tiles and analytics (every one of them cross-origin) and Next's same-origin RSC payloads, because those carry page content. A cached API answer would both leak on a shared clinic phone and show a stale voucher state. Icons are reproducible with `npm run icons` (`scripts/generate-icons.mjs`), the layout declares the manifest, icons, theme colour and iOS install metadata, and `tests/e2e/offline-shell.spec.ts` asserts the manifest, the decoded icon sizes, an offline reload served by the worker, and that no API or dynamic-route URL ever enters the cache.
- Low-bandwidth mode for slow, metered clinic connections (`src/lib/low-bandwidth.ts`, `LowBandwidthToggle`, `SwrProvider`, #75): a header switch remembered per browser that swaps the live-update stream for a 60s poll, stops SWR revalidating on focus and reconnect, skips the clinic map entirely — no Leaflet chunk, no OpenStreetMap tiles — and turns cookieless analytics off. Writes are untouched: contract calls are still built, simulated, signed and submitted exactly as before, and error reporting stays on. Measured on the home page with the map open, transmitted bytes drop from 748 KB to 438 KB at 1280px and from 562 KB to 409 KB at 390px (`tests/e2e/low-bandwidth-mode.spec.ts` measures bytes and asserts the traffic: no stream, no tiles, no analytics script).

## 0.2.0 — 2026-10-09

### Added
- Issue forms (bug, feature) and a pull request template; blank issues off, security reports routed to SECURITY.md.
- Testnet: **Get test USDC** on My vouchers and in the funding form, backed by the faucet contract. Shows the wallet's balance, the daily limit, and how to add the USDC trustline when it is missing.
- Clinic desk lists the clinic's services with Edit (prefills the form to change label or price) and Delist (two-click, calls `remove_service`).
- Funding shows what the clinic receives after the protocol fee, quoted live from the contract.
- Funders can generate a strong patient key in one click, with a prompt to save and share it.
- Funders choose how long the patient has to attend (14, 30, 60 or 90 days).
- After funding, a link straight to the new voucher's page.
- `/vouchers/[id]`: a shareable page for one voucher with its on-chain history (funded, seen, confirmed, dispute window, paid or refunded), receipt and the actions the connected wallet can take. Voucher numbers in lists link to it.
- Disputes ask what went wrong (reason codes 1–4) and need confirming; disputed vouchers show the reason.
- Vouchers and receipts show the service name instead of its code.
- Claimed vouchers say when they become refundable if no attester confirms.

### Fixed
- An unknown voucher or clinic (for example `/vouchers/99999`) showed the raw API error string; the voucher and clinic pages now call `notFound()` on a 404 and show a friendly page with a way back.
- A missing USDC trustline was reported as "The dispute window is still open", and an insufficient balance as "not in the right state": token errors come through with the token's own error numbers, which were looked up in the voucher table. Token messages are now recognised first.
- Clinic desk treated pending, suspended and unregistered clinics alike, so a clinic awaiting verification was offered the Register form again, which then failed. Status is now read from the registry and each state gets its own message.
- Services priced at 1,000 USDC or more could not be funded: the amount field was pre-filled with a thousands separator the parser rejects.
- Voucher amounts in lists showed seven decimals (`$3.0000000`); they now match the rest of the app.
- Switching wallets mid-load could show the previous wallet's vouchers.
- `npm run lint` works again (`next lint` was removed in Next 16) and runs in CI.

- Points at the 2026-10-07 testnet deployment.
